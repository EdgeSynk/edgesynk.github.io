# edgesynk.github.io

EdgeSynk의 3D 공간인지 기반 안전감시 솔루션을 소개하는 정적 홈페이지입니다. [운영 홈페이지](https://www.edgesynk.com/)

## 홈페이지 구성

`index.html`이 홈페이지의 시작 페이지입니다. HTML이 본문과 섹션을 구성하고, 상단 `<style>`은 디자인과 반응형 레이아웃을 담당합니다. 하단 JavaScript는 모바일 메뉴와 스크롤 애니메이션을 처리합니다. 수정한 파일을 별도의 빌드 과정 없이 열어볼 수 있습니다.

| 위치 | 역할 |
| --- | --- |
| 첫 화면 | EdgeSynk 소개, 3D LiDAR 스캔 이미지, 솔루션 및 협력 문의 링크 |
| `#business` · `#tech` | 안전감시 모듈, 관제 시스템, 구축 지원 및 센싱부터 알림까지의 처리 흐름 |
| `#application` · `#market` | 고령친화·산업현장 적용 시나리오, 서비스 네트워크 구성도 및 도입 배경 |
| `#differentiation` · `#roadmap` | 기존 방식과의 비교, 기술 개발과 사업화 계획 |
| `#contact` · 푸터 | 문의 링크와 회사 정보 |

화면 폭이 768px 이하이면 상단 **메뉴** 버튼으로 섹션을 선택합니다. 링크를 누르면 메뉴가 닫히고 해당 섹션으로 이동합니다. `Esc`로 닫으면 초점이 메뉴 버튼으로 돌아갑니다. JavaScript 사용이 제한된 환경에서는 섹션 링크를 가로로 스크롤할 수 있습니다.

| 파일·폴더 | 역할 |
| --- | --- |
| [`index.html`](index.html) | 운영 화면의 본문, 스타일, 스크립트 |
| [`images/`](images/) | `3d-3.png`는 첫 화면, `edgesynk-logo-1.png`는 헤더와 푸터, `safety_monitoring_architecture.svg`는 적용 시나리오에 사용 |
| [`CNAME`](CNAME) | GitHub Pages에 연결한 사용자 지정 도메인 `www.edgesynk.com` |
| `12-edgesynk_homepage-G.html` · `2-edgesynk_homepage.html` · `21-edgesynk_homepage.html` | 저장소에 남아 있는 별도 홈페이지 버전. 메인 화면에서 링크하지 않음 |

최근 수정에서는 첫 화면 이미지 태그를 고치고 모바일 메뉴를 추가했습니다. HTML에 직접 포함했던 로고와 구성도를 `images/`의 기존 파일로 연결해 `index.html`을 약 1.83MiB에서 26KiB로 줄였고, 공개 화면의 편집 가이드를 제거했습니다.

## 미리보기와 배포 확인

브라우저에서 저장소 폴더의 `index.html`을 바로 열 수 있습니다. HTTP 환경에서 확인하려면 Python이 설치된 PC의 터미널에서 저장소 폴더로 이동해 아래 명령을 실행한 뒤 [로컬 주소](http://127.0.0.1:8000/)를 엽니다.

```sh
python -m http.server 8000 --bind 127.0.0.1
```

수정한 부분을 데스크톱과 모바일 화면에서 확인합니다. 메뉴를 손봤다면 섹션 이동과 키보드로 열고 닫는 동작을 확인하고, 이미지나 링크를 손봤다면 해당 파일과 목적지가 열리는지 확인합니다. 배포 시에는 `main`에 들어간 커밋과 Pages 실행 결과를 대조하고, 운영 도메인에서 변경된 화면을 확인합니다. [GitHub Actions](https://github.com/EdgeSynk/edgesynk.github.io/actions) · [운영 홈페이지](https://www.edgesynk.com/)

## 앞으로 할 일

### 우선 처리

- [ ] **데모 문의 연결.** 현재 `데모 요청하기`는 `href="#"`를 사용합니다. 실제 접수 이메일이나 신청 폼을 정해 연결하고, 문의가 담당자에게 전달되는지 테스트합니다.
- [ ] **제품 설명 정합성 확인.** 본문의 LiDAR·오디오 설명과 구성도의 `Camera` 표기를 실제 제품 사양에 맞춥니다. 감지 성능, 비식별 처리, 법적 의무에 관한 문구는 확인된 근거와 적용 조건을 반영합니다. 로드맵에는 완료·진행·계획을 구분해 표시합니다.
- [ ] **모바일 사용성 확인.** 휴대폰에서 메뉴와 섹션 이동을 직접 점검합니다. 차별성 비교표는 좁은 화면에서도 각 설명이 기존 방식과 EdgeSynk 중 어느 쪽인지 표시하고, 네트워크 구성도의 작은 글씨가 읽히는지 확인합니다.

### 다음 개선

- [ ] **검색과 링크 공유 준비.** 페이지 설명, 대표 URL, Open Graph 공유 이미지, 파비콘을 추가하고, 실제 링크 미리보기에서 제목과 이미지가 의도대로 보이는지 확인합니다.
- [ ] **이미지 전송량 줄이기.** 첫 화면 스캔 이미지와 로고의 실제 표시 크기와 원본 용량을 비교합니다. 시각적 품질을 유지하는 선에서 해상도 조정, WebP 변환, 화면 크기별 이미지 제공을 검토합니다.
- [ ] **예전 홈페이지 파일 정리.** 별도 HTML과 사용처가 불명확한 이미지의 외부 링크 및 보관 필요성을 확인합니다. 정리 전 필요한 버전은 Git 이력이나 별도 보관 위치에서 찾을 수 있게 합니다.
- [ ] **콘텐츠 확장 준비.** 제품별 설명, 실증 사례, 기술 자료 중 실제로 반복해서 게시할 콘텐츠가 무엇인지 정합니다. 공개할 수 있는 설치 환경, 감지 시나리오, 검증 결과를 확보한 뒤 상세 페이지의 공통 구성을 설계합니다.

### Astro로의 전환

현재는 한 페이지로 운영 중이므로 데모 문의와 제품 설명 개선을 우선합니다. 제품 상세, PoC·실증 사례, 기술 자료를 여러 페이지로 발행하고 공통 메뉴와 푸터를 관리할 필요가 생기면 Astro 전환을 시작합니다.

- [ ] **기존 홈페이지 이식.** 별도 브랜치에서 `index.html`을 `src/pages/index.astro`로 옮기고, 첫 화면과 주요 섹션을 데스크톱·모바일에서 기존 홈페이지와 비교합니다.
- [ ] **레이아웃과 콘텐츠 구성.** 메뉴와 푸터를 공통 레이아웃으로 분리합니다. 기본 상세 페이지를 한 개 만들어 탐색 흐름을 검증하고, 반복해서 발행할 실증 사례와 기술 글은 Markdown으로 관리합니다. 글마다 제목과 날짜 같은 공통 항목을 검증할 필요가 있으면 콘텐츠 컬렉션을 사용합니다. [Astro 구성 요소](https://docs.astro.build/en/basics/astro-components/) · [콘텐츠 컬렉션](https://docs.astro.build/en/guides/content-collections/)
- [ ] **배포 전 검증.** 정적 빌드 결과에서 기존 섹션 주소, 이미지 경로, 모바일 메뉴와 문의 링크를 확인합니다. `public/CNAME`과 Astro 설정의 `site` 값에 `www.edgesynk.com`을 반영합니다.
- [ ] **운영 전환.** 검증이 끝나면 GitHub Actions로 정적 빌드 결과를 GitHub Pages에 배포하고, 기존 운영 도메인에서 메인 페이지와 상세 페이지가 열리는지 확인합니다. [Astro의 GitHub Pages 배포 가이드](https://docs.astro.build/en/guides/deploy/github/)
