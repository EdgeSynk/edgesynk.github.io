# edgesynk.github.io

EdgeSynk의 3D 공간인지 기반 안전감시 솔루션을 소개하는 정적 홈페이지입니다. [운영 홈페이지](https://www.edgesynk.com/)

## 홈페이지 구성

`index.html`은 기본 한국어 페이지이고, `en/index.html`은 영어 페이지입니다. 상단의 **EN** 또는 **한국어** 링크로 언어를 바꿀 수 있습니다. 두 페이지는 `site.css`와 `site.js`를 공유하며 별도의 빌드 없이 열 수 있습니다.

| 위치 | 역할 |
| --- | --- |
| 첫 화면 | EdgeSynk 소개, 3D LiDAR 스캔 이미지, 솔루션 및 협력 문의 링크 |
| `#business` · `#tech` | 안전감시 모듈, 관제 시스템, 구축 지원 및 센싱부터 알림까지의 처리 흐름 |
| `#application` · `#market` | 고령친화·산업현장 적용 시나리오, 서비스 네트워크 구성도 및 도입 배경 |
| `#differentiation` · `#roadmap` | 기존 방식과의 비교, 기술 개발과 사업화 계획 |
| `#contact` · 푸터 | 문의 링크와 회사 정보 |

화면 폭이 880px 이하이면 상단 **메뉴** 버튼으로 섹션을 선택합니다. 링크를 누르면 메뉴가 닫히고 해당 섹션으로 이동합니다. `Esc`로 닫으면 초점이 메뉴 버튼으로 돌아갑니다. JavaScript 사용이 제한된 환경에서는 섹션 링크를 가로로 스크롤할 수 있습니다.

| 파일·폴더 | 역할 |
| --- | --- |
| [`index.html`](index.html) · [`en/index.html`](en/index.html) | 한국어·영어 페이지의 본문 |
| [`site.css`](site.css) · [`site.js`](site.js) | 공통 스타일, 모바일 메뉴, 스크롤 애니메이션, 언어 전환 시 섹션 유지 |
| [`images/`](images/) | `3d-3.png`는 첫 화면, `edgesynk-logo-1.png`는 헤더와 푸터, `safety_monitoring_architecture.svg`와 `_en.svg` 버전은 언어별 적용 시나리오에 사용 |
| [`CNAME`](CNAME) | GitHub Pages에 연결한 사용자 지정 도메인 `www.edgesynk.com` |
| `12-edgesynk_homepage-G.html` · `2-edgesynk_homepage.html` · `21-edgesynk_homepage.html` | 저장소에 남아 있는 별도 홈페이지 버전. 메인 화면에서 링크하지 않음 |

최근 수정에서는 첫 화면 이미지 태그를 고치고 모바일 메뉴를 추가했습니다. HTML에 직접 포함했던 로고와 구성도를 `images/`의 기존 파일로 연결해 `index.html`을 약 1.83MiB에서 26KiB로 줄였고, 공개 화면의 편집 가이드를 제거했습니다.

## 미리보기와 배포 확인

브라우저에서 저장소 폴더의 `index.html`을 바로 열 수 있습니다. HTTP 환경에서 확인하려면 Python이 설치된 PC의 터미널에서 저장소 폴더로 이동해 아래 명령을 실행한 뒤 [로컬 주소](http://127.0.0.1:8000/)를 엽니다.

```sh
python -m http.server 8000 --bind 127.0.0.1
```

HTTP 미리보기에서 [한국어 `/`](http://127.0.0.1:8000/)와 [영어 `/en/`](http://127.0.0.1:8000/en/)를 각각 확인합니다.

## 협업 개발 규칙

### 작업 시작

1. `git status --short --branch`로 현재 브랜치와 수정 파일을 확인합니다. 이전 작업은 보존하고, 이번 작업의 목적과 변경 범위를 먼저 공유합니다.
2. 운영 반영을 준비할 때는 작업 브랜치에서 관련 변경을 묶어 검토 요청(PR)을 올립니다. PR에는 **바뀐 내용, 검증 결과, 남은 확인 사항**을 적고, 화면을 수정했다면 전후 화면을 첨부합니다.

### 콘텐츠와 코드 수정

- **한·영 동시 수정.** 메뉴, 본문, 버튼, 이미지 대체 텍스트, 구성도 안의 글자, 회사 정보는 해당 항목이 바뀔 때 두 언어를 함께 맞춥니다. 번역에서 수치, 적용 조건, 제품 사양과 로드맵 상태의 의미를 유지합니다. 본문과 구성도의 센서·데이터 처리 설명을 실제 사양과 대조하고, 감지 성능이나 법적 의무를 추가할 때는 공개 가능한 근거와 적용 범위를 확인합니다.
- **주소와 섹션 유지.** 한국어 `/`, 영어 `/en/`, `#tech` 같은 기존 섹션 주소를 유지합니다. 새 섹션은 두 페이지에 같은 ID를 사용합니다. 페이지 주소를 바꿀 때는 기존 공유 링크의 연결 방법과 두 페이지의 `lang`, `canonical`, `hreflang`을 함께 확인합니다.
- **공통 파일 재사용.** 공통 디자인은 `site.css`, 양쪽에서 쓰는 동작은 `site.js`에 둡니다. 새 이미지는 사용 권한을 확인해 `images/`에 추가하고, 언어별 페이지에서 경로가 열리는지 확인합니다. 배포 방식이나 도메인(`CNAME`)을 바꾸는 작업은 콘텐츠 변경과 별도 PR로 검토합니다.
- **문의 경로 확인.** 문의 버튼은 담당자가 확인한 이메일 또는 폼에 연결합니다. 접수 경로를 신설하거나 변경할 때는 양쪽 페이지에서 같은 접수처로 연결되는지 확인하고, 테스트 문의가 담당자에게 도착했는지 확인합니다.

### 검증과 배포

- **수정 내용에 맞춰 검증.** 화면이나 기능을 바꾸면 한·영 페이지를 모바일·데스크톱에서 열어 변경한 항목을 확인합니다. 메뉴나 언어 전환을 수정했다면 **880px·881px**에서 메뉴 표시를 비교하고, `Esc`로 닫을 때 초점이 돌아오는지, `#tech` 같은 섹션에서 언어를 바꿔도 위치가 유지되는지 확인합니다. 반응형 본문을 수정했다면 **768px·769px**에서 레이아웃 전환을 확인합니다. 문서만 수정할 때는 문서 링크와 `git diff --check`를 확인합니다.
- **검토 후 배포.** 운영 반영 범위에 동의한 변경을 `main`에 병합합니다. 병합 커밋과 GitHub Pages 실행 결과를 대조한 뒤 운영 도메인의 `/`와 `/en/`에서 변경 사항을 확인합니다. 작업 기록에는 **로컬 확인, Pages 배포, 운영 화면 확인** 중 어디까지 끝났는지 적습니다. [GitHub Actions](https://github.com/EdgeSynk/edgesynk.github.io/actions) · [운영 홈페이지](https://www.edgesynk.com/)
- **배포 후 복구.** 주요 화면이나 문의 경로가 깨지면 원인 커밋을 확인하고 그 변경만 되돌리는 PR을 검토합니다. 복구 배포가 끝나면 운영 도메인의 두 언어 페이지와 영향받은 기능을 다시 확인합니다.

## 앞으로 할 일

### 우선 처리

- [ ] **데모 문의 연결.** 현재 `데모 요청하기`는 `href="#"`를 사용합니다. 실제 접수 이메일이나 신청 폼을 정해 연결하고, 문의가 담당자에게 전달되는지 테스트합니다.
- [ ] **제품 설명 정합성 확인.** 본문의 LiDAR·오디오 설명과 구성도의 `Camera` 표기를 실제 제품 사양에 맞춥니다. 감지 성능, 비식별 처리, 법적 의무에 관한 문구는 확인된 근거와 적용 조건을 반영합니다. 로드맵에는 완료·진행·계획을 구분해 표시합니다.
- [ ] **모바일 사용성 확인.** 휴대폰에서 메뉴와 섹션 이동을 직접 점검합니다. 차별성 비교표는 좁은 화면에서도 각 설명이 기존 방식과 EdgeSynk 중 어느 쪽인지 표시하고, 네트워크 구성도의 작은 글씨가 읽히는지 확인합니다.

### 다음 개선

### Astro로의 전환

현재는 한국어와 영어로 같은 랜딩 페이지를 제공하는 구조이므로 데모 문의와 제품 설명 개선을 우선합니다. 제품 상세, PoC·실증 사례, 기술 자료를 여러 페이지로 발행하고 공통 메뉴와 푸터를 관리할 필요가 생기면 Astro 전환을 시작합니다.

- [ ] **기존 홈페이지 이식.** 별도 브랜치에서 `index.html`을 `src/pages/index.astro`로 옮기고, 첫 화면과 주요 섹션을 데스크톱·모바일에서 기존 홈페이지와 비교합니다.
- [ ] **레이아웃과 콘텐츠 구성.** 메뉴와 푸터를 공통 레이아웃으로 분리합니다. 기본 상세 페이지를 한 개 만들어 탐색 흐름을 검증하고, 반복해서 발행할 실증 사례와 기술 글은 Markdown으로 관리합니다. 글마다 제목과 날짜 같은 공통 항목을 검증할 필요가 있으면 콘텐츠 컬렉션을 사용합니다. [Astro 구성 요소](https://docs.astro.build/en/basics/astro-components/) · [콘텐츠 컬렉션](https://docs.astro.build/en/guides/content-collections/)
- [ ] **배포 전 검증.** 정적 빌드 결과에서 기존 섹션 주소, 이미지 경로, 모바일 메뉴와 문의 링크를 확인합니다. `public/CNAME`과 Astro 설정의 `site` 값에 `www.edgesynk.com`을 반영합니다.
- [ ] **운영 전환.** 검증이 끝나면 GitHub Actions로 정적 빌드 결과를 GitHub Pages에 배포하고, 기존 운영 도메인에서 메인 페이지와 상세 페이지가 열리는지 확인합니다. [Astro의 GitHub Pages 배포 가이드](https://docs.astro.build/en/guides/deploy/github/)
